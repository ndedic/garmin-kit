The `garmin` CLI is on PATH (see https://github.com/ndedic/garmin-kit). It only reads Garmin data (it never writes to the Garmin account, and this skill never saves files) and the API key is already configured; never ask the user for a CLI path or an API key. If the user explicitly wants a file saved, tell them to run `garmin download` themselves.

## Commands
Start with `garmin analyse` for any "my last run" question; drill into raw commands only if it isn't enough. Prefer `--every-seconds 30` or more with `records`; never dump all ~2,000 samples.

- `garmin runs [--limit N] [--date DATE]` — List recent running activities (raw Garmin summaries, newest first). Use to find activity IDs.
- `garmin analyse [ACTIVITY_ID]` — Compact summary of a run: totals, per-km splits, first/second-half pace and HR, HR drift, pacing label, comparison with the previous 3 runs, and recovery context (sleep, HRV, resting HR, Body Battery going into the run). Defaults to the latest run. Contains no name or GPS data. Best starting point for any question about a run.
- `garmin activity ACTIVITY_ID` — Raw Garmin activity detail JSON. Verbose and includes location data; prefer analyse_run.
- `garmin laps ACTIVITY_ID` — Parsed FIT lap messages for an activity (raw, verbose). Prefer analyse_run for splits.
- `garmin records ACTIVITY_ID [--every-seconds N]` — Per-second FIT samples (HR, speed, altitude, GPS) for an activity. Very large; downsample with everySeconds.
- `garmin sleep [--date DATE]` — Detailed sleep for one night: duration, stages, sleep score, overnight HR/HRV/respiration. Large; use get_sleep_summaries for trends.
- `garmin sleep-summaries [--start-date START_DATE] [--end-date END_DATE]` — Per-night sleep summaries over a date range (default last 7 days, max 90).
- `garmin hrv [--date DATE]` — Overnight heart rate variability for one date: summary, status and readings.
- `garmin hrv-summaries [--start-date START_DATE] [--end-date END_DATE]` — Daily HRV summaries over a date range (default last 7 days, max 90). Good for recovery trends.
- `garmin body-battery [--start-date START_DATE] [--end-date END_DATE]` — Body Battery energy levels over a date range (default last 7 days, max 90).
- `garmin heart-rate [--date DATE]` — All-day heart rate for one date, including resting heart rate.
- `garmin daily-summaries [--start-date START_DATE] [--end-date END_DATE]` — Daily wellness summaries over a date range (default last 7 days, max 90): steps, resting HR, stress and more.
- `garmin last-run` — shorthand for `garmin runs --limit 1`.

## Reading the output
- Units are in the field names (`distance_km`, `pace_min_per_km`, `cadence_spm`). Cadence is already steps per minute.
- `splits` may include a tiny split (for example 9 m) caused by a watch lap press; ignore it when judging pace.
- `pacing` and `hr_drift_bpm` compare the first and second half. Rising HR at the same pace suggests fatigue or heat; HR rising with a faster pace is expected effort.
- `vs_previous` compares with the previous 3 runs; a negative pace delta means faster.

## Reporting
Lead with the verdict in one or two sentences, then the evidence: pacing pattern, HR trend, how it compares with recent runs, training load. Be honest about effort. If a hard run follows easy ones, say so and mention recovery. Don't paste raw JSON back. Don't speculate on health or medical conditions from HR data; suggest seeing a professional if anything looks concerning.
Data is private (health, location): don't send it anywhere outside this conversation.
