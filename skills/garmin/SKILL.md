The `garmin` CLI is on PATH (see https://github.com/ndedic/garmin-kit). It is read-only and the API key is already configured; never ask the user for a path or key.

## Commands
Start with `garmin analyse` for any "my last run" question; drill into raw commands only if it isn't enough. Prefer `--every-seconds 30` or more with `records`; never dump all ~2,000 samples.

- `garmin runs [--limit N] [--date VALUE]` — List recent running activities (raw Garmin summaries, newest first). Use to find activity IDs.
- `garmin analyse [ACTIVITY_ID]` — Compact summary of a run: totals, per-km splits, first/second-half pace and HR, HR drift, pacing label, comparison with the previous 3 runs. Defaults to the latest run. Contains no name or GPS data. Best starting point for any question about a run.
- `garmin activity ACTIVITY_ID` — Raw Garmin activity detail JSON. Verbose and includes location data; prefer analyse_run.
- `garmin laps ACTIVITY_ID` — Parsed FIT lap messages for an activity (raw, verbose). Prefer analyse_run for splits.
- `garmin records ACTIVITY_ID [--every-seconds N]` — Per-second FIT samples (HR, speed, altitude, GPS) for an activity. Very large; downsample with everySeconds.
- `garmin download ACTIVITY_ID [--format fit|zip|json] [--output VALUE]` — Save an activity's FIT file (or Garmin's ZIP, or FIT parsed to JSON) to disk. Refuses to overwrite.
- `garmin last-run` — shorthand for `garmin runs --limit 1`.

## Reading the output
- Units are in the field names (`distance_km`, `pace_min_per_km`, `cadence_spm`). Cadence is already steps per minute.
- `splits` may include a tiny split (for example 9 m) caused by a watch lap press; ignore it when judging pace.
- `pacing` and `hr_drift_bpm` compare the first and second half. Rising HR at the same pace suggests fatigue or heat; HR rising with a faster pace is expected effort.
- `vs_previous` compares with the previous 3 runs; a negative pace delta means faster.

## Reporting
Lead with the verdict in one or two sentences, then the evidence: pacing pattern, HR trend, how it compares with recent runs, training load. Be honest about effort. If a hard run follows easy ones, say so and mention recovery. Don't paste raw JSON back. Don't speculate on health or medical conditions from HR data; suggest seeing a professional if anything looks concerning.
Data is private (health, location): don't send it anywhere outside this conversation.
